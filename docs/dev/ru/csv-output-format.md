# Формат выходного CSV

[English version](../csv-output-format.md)

CSV-адаптер записывает изменяемые канонические проекции и неизменяемые срезы
экспорта с одной политикой байтов. Она задаёт окончания записей и кавычки
независимо для заголовков и данных. Разбор импорта имеет собственный диалект
контракта; изменение выходных настроек не меняет контракт импорта.

## Ход выполнения

```text
typed configuration -> semantic preflight -> ExportFormat
    -> canonical snapshot -> shared CSV formatter -> temporary output
    -> atomic projection replacement / verified immutable slice publication
```

Bootstrap один раз разрешает политику для обоих выходных путей. Прикладная
модель содержит перечисления без зависимостей от фреймворков. Commons CSV
обрабатывает поля с кавычками в адаптере; строгий вывод без кавычек проверяет
всю запись до добавления. Форматирование не меняет канонические значения,
идентичность, TTL и происхождение.
Изменяемые файлы заменяются по артефактам, а не одним атомарным набором.
Используется временный файл рядом с целевым и требуется атомарная замена;
неатомарного резервного варианта нет. Неизменяемый экспорт публикует проверенный
каталог профиля отдельным протоколом подготовки, manifest и marker.

## Инварианты

1. Окончания записей явно заданы как LF или CRLF и не зависят от платформы.
   Настройка разделяет записи, не переписывая переводы строк внутри ячеек с
   кавычками.
2. Заголовки и значения независимо выбирают `all`, `minimal` или `none`.
   `all` заключает в кавычки каждую ячейку, отличную от null. Отсутствующее
   значение во всех режимах представляется маркером null без кавычек.
   `minimal` делегирует обычные кавычки и экранирование Commons CSV, а также
   заключает в кавычки буквальный текст, равный маркеру null.
3. `none` не добавляет кавычки и символы экранирования. Разделитель, кавычка,
   CR и LF внутри ячейки вызывают отказ. Значение, равное маркеру null, и
   одноколоночная запись с пустым текстом также отклоняются из-за неоднозначности.
   Пустые ячейки многоколоночной записи представимы.
4. Маркер null сам не содержит синтаксис CSV. Потребитель должен различать
   текст в кавычках и маркер без кавычек, чтобы сохранить буквальный `NULL`;
   отдельные правила null-literals управляемого импорта не меняются.
5. Прежние настройки сохраняют точные байты CSV v1, байты manifest и хеш плана.
   Новый вариант включает все параметры политики в хеш плана и формирует
   manifest v2 с `record_separator`, `header_quoting` и `value_quoting`.
   Кодек читает обе версии; v2 требует все три поля. Неизвестные версии,
   политики и поля отклоняются. Потребителя только v1 нужно обновить до
   включения нового формата.
6. Восстановление читает сохранённый manifest и файлы. Оно не переписывает
   старый срез текущими настройками. Изменение формата CSV не требует миграции
   схемы БД и не меняет хеши схемы артефакта и отображения.

## Примеры наблюдаемых байтов

При разделителе `;`, кавычке `"`, маркере null `NULL` и ALL/ALL заголовок из
двух колонок и строки с отсутствующим значением и буквальным текстом `NULL`
выглядят так:

```text
"id";"value"\r\n
"1";NULL\r\n
"2";"NULL"\r\n
```

Каждое показанное `\r\n` обозначает фактические два символа окончания записи;
перевод строки для отображения не добавляет запись в выход. Пустой текст
отличается от отсутствующего значения: ALL пишет `""`, отсутствие остаётся
некавыченным `NULL`. MINIMAL также заключает в кавычки буквальный `NULL` и текст
с синтаксисом, например `semi;colon`; NONE отклоняет неоднозначные и содержащие
синтаксис ячейки данных. Имена заголовков не являются nullable-данными:
заголовок `NULL` без кавычек разрешён, если иначе представим. Потребители должны
использовать согласованные правила null и кавычек.

## Отказы и восстановление

| Отказ | Результат |
|---|---|
| Некорректный селектор или грамматика CSV | Конфигурация отклоняется до запуска рабочей инфраструктуры. |
| Непредставимая ячейка в `none` | Вывод завершается ошибкой с позицией колонки без исходного значения ячейки. |
| Ошибка кодирования, форматирования или записи проекции до замены | Временный файл удаляется, предыдущий установленный файл сохраняется. Канонические данные уже могут быть записаны и не откатываются. |
| Файловая система не поддерживает атомарную замену | Проекция отказывает без перехода к записи на месте или неатомарной замене. |
| Отказ материализации неизменяемого среза | Итоговый срез не публикуется; частичная подготовка, включая уже записанный там marker, подчиняется обычному восстановлению экспорта. |
| Перезапуск после материализации | Восстановление определяют существующие checksum, manifest и marker независимо от текущего формата. |

Изменяемые проекции допускают диагностированную замену непредставимых символов
только при `all` для заголовков и значений. `minimal` или `none` хотя бы для
одной группы включает строгое кодирование: замена иначе могла бы добавить
разделитель или кавычку вне кавычек. Неизменяемые срезы всегда кодируются строго,
так как потеря данных нарушает контракт экспорта. UTF-8 используется по умолчанию
и поддерживает весь корректный текст Unicode.

## Конфигурация

Для LF, заголовков в кавычках и строго некавыченных данных:

```yaml
ioc:
  sink:
    csv:
      record-separator: lf
      header-quoting: all
      value-quoting: none
```

Для обычных заголовков без кавычек и данных в кавычках задайте
`header-quoting: none` и `value-quoting: all`. Используйте `minimal`, если значения
с синтаксисом CSV должны автоматически заключаться в кавычки. Отсутствующие
параметры сохраняют `crlf`, `all`, `all`.

Настройки общие для всех артефактов и профилей экспорта с `ioc.sink.csv`. Они
не меняют исторические файлы и не применяют конфигурацию к установленному сервису
автоматически. Изменяемый файл получит новый формат при следующем построении
проекции; изменение настроек само по себе не помечает канонические поколения
изменёнными. Предварительный допуск неизменяемого экспорта включает новый хеш
плана и поэтому формирует новый срез при следующем допустимом экспорте даже без
изменения канонических строк.
