# Контролируемые отчёты об ошибках конфигурации

[English version](../configuration-failure-reports.md)

IOC преобразует ошибки конфигурации в операторские отчёты с фиксированными
категориями, путями объявленных полей и рекомендациями. Эта граница охватывает
проверку YAML, семантическую команду и собственные анализаторы YAML и неизвестных
имён IOC. Она не очищает произвольные логи фреймворка и не заменяет политику
валидации и восстановления сервиса.

## Ход выполнения

```text
YAML loading / Spring binding and validation / IOC registry preflight
  -> recognize structured failure
  -> retain allowed coordinates and schema paths
  -> render fixed IOC code and guidance
  -> command exits 78, or Boot presents the owned failure analysis
```

Семантическая команда запускает ограниченный контекст настроек. В нём участвуют
classpath defaults, candidate, разрешённые импорты Boot и эффективные
переопределения. Рабочие хранилища, транспорт и планировщики не сканируются.
Подавление консоли локально для команды и временно меняет потоки процесса;
использовать её как встраиваемый обработчик общего процесса нельзя. Ограниченный
граф бинов не обеспечивает изоляцию ресурсов.

## Границы ответственности

Bootstrap владеет отчётами, кодами `CONFIG.*`, политикой отображения полей,
рекомендациями и кодами завершения. Общий инспектор конфигурации остаётся API
объявлений; он не получает зависимость от YAML, вывод исключений или контроль
запуска. Spring отвечает за binding и валидацию. IOC — за семантику и реестры.

`IocConfigurationCheckFailure` — внутренняя неизменяемая проекция неуспешной
семантической проверки: одна категория и неизменяемый список путей. Исходное
исключение она не хранит. Сведения YAML сохраняют только числовые строку и
столбец; метки источников задаёт вызывающий код IOC. Наблюдения неизвестных имён
отделены от ошибок binding и валидации с путями, подтверждёнными схемой.

## Инварианты

1. **Не копировать диагностический текст обработки ошибочного ввода.** Текст
   parser problem, сообщения исключений, произвольные имена классов, стандартные
   сообщения валидаторов, отклонённые значения, аргументы, пользовательские коды и
   произвольные результаты origin `toString()` не входят в контролируемый отчёт.
   Усечение текста не является удалением секретов.
2. **Сохранять полезные координаты без динамических ключей словарей.** Binding
   использует наиболее точное структурное имя `BindException`. Валидация — корень
   проверки и пути полей; глобальная ошибка использует корень. Отображение
   останавливается на последнем объявленном поле записи IOC или числовом индексе.
   Camel-case пути валидатора и kebab-case пути binding сохраняют написание.
   В словарях отображение останавливается на поле словаря и может быть менее
   точным, чем исходная ошибка.
3. **Раскрытие имён — явная политика сервиса.** Неизвестные имена и исходные имена
   переменных окружения видны для исправления опечаток и миграции. Такие имена,
   числовые индексы и имена candidate-файлов не универсально безопасны.
   Только типизированная метка имени IOC может передавать проверенное имя
   окружения через прежний механизм unbound-property; произвольная отклонённая
   строка не может.
4. **Не прикреплять исходное исключение к собственному анализу Boot.** Boot может
   записать причину анализа на DEBUG. Поэтому анализы YAML и неизвестных имён
   не содержат cause. Исходная ошибка остаётся у вызывающего фреймворка или кода,
   за пределами этого отчёта.
5. **Не приписывать невыполненные фазы.** Ошибка binding не подтверждает
   семантическую проверку и проверку реестров. Валидация сообщает доступные
   нарушения, включая несколько полей, но не доказывает запуск всех остальных
   валидаторов. Отказ реестра распознаётся по собственному типу исключения IOC,
   а не поиском кода в подробном сообщении.

## Ошибки и восстановление

Следующие категории описывают контролируемый вывод команды. Обычный запуск
использует собственные анализаторы YAML и неизвестных имён IOC, когда они
применимы; таблица не обещает вывод каждой обычной ошибки Boot через проекцию
команды.

| Ситуация | Контролируемый результат | Что остаётся неизвестным |
|---|---|---|
| Некорректный вызов checker | `CONFIG.YAML_USAGE` или `CONFIG.SEMANTIC_USAGE`, код 78 | Успешной проверки нет; пустой путь YAML-only получает `CONFIG.YAML_UNREADABLE` |
| Файл отсутствует/недоступен или путь некорректен | `CONFIG.YAML_UNREADABLE`; некорректный путь семантической команды получает `CONFIG.SEMANTIC_UNREADABLE` | Успешные разбор, binding и валидация не подтверждены |
| Синтаксическая ошибка YAML | `CONFIG.YAML_INVALID`, необязательные строка/столбец с единицы, фиксированная рекомендация | Проверки имён, binding, семантики и реестров не завершены |
| Запрещённые объявления `spring.main.sources` | `CONFIG.SEMANTIC_SOURCE_OVERRIDE` внутри общей семантической ошибки | Ограниченный набор источников контекста не принят |
| Неизвестное или удалённое имя IOC | `CONFIG.UNKNOWN_PROPERTY`, имена, применимые подсказки `CONFIG.LEGACY_*` | Успешный binding и последующие проверки |
| Ошибка binding/преобразования | `CONFIG.BINDING_FAILED`, путь по схеме, рекомендация по типам и значениям | Результаты семантической проверки и проверки реестров |
| Ошибка поля или общей валидации | `CONFIG.VALIDATION_FAILED`, различные пути, рекомендация по ограничениям | Принятие всей конфигурации и результаты реестров |
| Отказ реестра или плана обработки | `CONFIG.REGISTRY`, фиксированная рекомендация по ссылкам и планам | Принятие всей конфигурации |
| Нераспознанная ошибка выполнения | `CONFIG.CHECK_FAILED`, фиксированная рекомендация по исследованию | Категория ошибки и завершённость валидации |

После успешного разбора синтаксиса ошибки контекста получают оболочку
`CONFIG.SEMANTIC_INVALID` и код 78. Более ранние ошибки вызова, чтения и синтаксиса
сохраняют собственные коды без этой оболочки. Успех обозначается
`CONFIG.YAML_VALID` или `CONFIG.SEMANTIC_VALID` и кодом 0; YAML-only подтверждает
только синтаксис. `CONFIG.CHECK_FAILED` означает незавершённую проверку, а не
доказанную ошибку оператора. JVM `Error` эта граница не перехватывает. Подробное
техническое исследование требует отдельной контролируемой диагностической
политики; копирование исходного исключения в операторский отчёт вернуло бы
утечку данных.

Обычный запуск и сторонние анализаторы и логгеры могут выводить собственные
исключения. В частности, загрузка YAML в Spring может записывать содержимое
документа на DEBUG; произвольные appenders не подчиняются подавлению консоли.
Эти отчёты не гарантируют отсутствие секретов во всём выводе процесса.

Для оператора отказ предварительной проверки означает исправление отдельного
candidate и повторную проверку до apply. Проверяйте все эффективные источники:
причиной может быть переменная окружения, свойство JVM или импортированный
документ, даже если candidate выглядит правильным. Незавершённая проверка
требует исследования загрузки источников или окружения checker до признания
конфигурации принятой.

Сами отчёты не выполняют откат. Установленный помощник владеет атомарной заменой
YAML, перезапуском, проверкой health и восстановлением файла. Восстановленный
файл не отменяет изменения рабочего состояния и не доказывает здоровье сервиса;
следуйте [операторской процедуре](../../guides/ru/configuration.md#how-configuration-is-applied).

## Контракт расширения

Будущий общий адаптер должен сохранять фазу, фиксированную категорию,
необязательный путь по схеме или координаты, доступность ссылки на источник и
неполное/нераспознанное покрытие. Синтаксические ошибки и ошибки binding должны
явно оставлять последующие фазы неподтверждёнными. Неизвестные, неоднозначные и
непроверенные объявления сохраняют различия инспектора. Исключение, переданное
значение, сообщение, аргумент и произвольный объект источника не входят в
экспортируемый отчёт. Сервис преобразует факты в серьёзность, коды и действия.

Это граница данных и ответственности для дальнейшего выделения. Она не
объявляет публичный Java API и не обещает моделирование всех фаз внутренней
проекцией IOC. Добавляйте адаптер фреймворка при наличии независимых примеров
потребителя; сохраняйте прямые объявления зависимостей, не полагаясь на
случайные транзитивные зависимости.
