# Инспекция объявлений конфигурации

[English version](../configuration-inspection.md)

Spring Boot adapter проверяет объявленные имена по явной record-схеме и сообщает
упорядоченные наблюдения источников. Сервис владеет настройками, семантической
валидацией, кодами диагностики, правилами вывода и решениями по результатам.
Boot владеет binding, преобразованием значений и приоритетами.

Распределение ответственности закреплено в
[ADR 0046](../../ADR/0046-reusable-spring-boot-configuration-inspection.md).
[Руководство потребителя](../../guides/ru/libraries/config-spring-boot.md)
объясняет подключение; этот документ описывает внутренний поток и инварианты.

## Поток исполнения

```text
prepared schema + stable ordered PropertySources
  -> schema coverage + name-only source traversal
  -> immutable declarations, candidate paths and source coverage
  -> optional migration observations from explicit service descriptors
  -> service-selected strict check / source report
  -> ordinary Boot binding and semantic validation
```

Значения не читаются, environment и объекты источников не сохраняются в результате.
Само перечисление имён может завершиться ошибкой; эта операционная ошибка
передаётся вызывающему коду. Нет durable state, retry, reload, фоновых задач
или автоматического поиска beans.
Гарантия проверки только имён относится к инспекторам. Загрузка источников,
проверка placeholders в рецепте, Binder и семантическая валидация читают значения
по собственным контрактам. Callback перечисления пользовательского источника
также может выполнять произвольную работу; инспектор её не изолирует.

## Границы

[Рецепт ограниченного контекста](../../guides/ru/libraries/config-spring-boot-check.md)
разделяет выбор beans и загрузку источников. IOC сохраняет эффективные источники,
imports и profiles Boot; пример collector принимает один явный YAML-документ
и literal overrides, не вызывая ConfigData. Его точный Java-пример выполняется
в отдельной JVM без классов IOC. Общий инспектор не навязывает ни одну политику:
он получает уже подготовленные источники.

`adapters/adapter-config-spring-boot` зависит от Spring Boot и Spring Core.
Текущий IOC-потребитель — bootstrap; core и platform не могут импортировать
библиотеку. [Справочник модуля](../../../adapters/adapter-config-spring-boot/README.md)
содержит публичные типы, поддерживаемые структуры и соглашения об источниках.

Одна инспекция возвращает и результаты проверки имён, и наблюдения объявлений.
Она не выполняет два отдельных обхода и не делает reflection/tokenizer helpers
частью публичного API. `KNOWN` означает поддерживаемый путь, а не допустимое
значение. `UNKNOWN`, `AMBIGUOUS` и `UNSUPPORTED` различаются; неполное покрытие
не даёт оснований уверенно назвать операторский ключ неизвестным.

Покрытие описывает схему и фактически переданные источники. Пустая
последовательность, посторонний namespace или только намеренные исключения могут
дать `complete()` без объявлений. Обязательные настройки и выбор правильных
входов проверяет сервис. Aggregate исключается по точному имени источника
`configurationProperties`, до выбора ветви по типу; вызывающий код должен
зарезервировать это имя для Boot aggregate и отдельно передать конкретные источники.

## Развитие конфигурации

`MigrationInspector` получает неизменяемый `PropertyInspection` и явные
дескрипторы `PropertyMigration`. Он повторно использует внутренний matcher имён
с деревом для каждого старого пути и принимает только полные совпадения шаблона.
Объявление контейнера record или list не означает объявления дочерних полей.
Этот шаг не перечисляет источники, не читает значения и ничего не меняет.

Например, дескриптор `collector.connections[].legacy-timeout` даёт подсказку
`collector.connections[3].request-timeout`, если объявлен индекс `[3]`.
Удалённые пути распознаются без возврата tombstone fields в текущую record-схему.
Исходная находка неизвестного имени сохраняется. Текущие schema candidates
участвуют в проверке неоднозначности, включая конфликт удалённого плоского поля
с текущим вложенным environment-путём. Эквивалентные record-написания сравниваются
без дефисов, с сохранением точек и индексов.

[Migration API](../../../adapters/adapter-config-spring-boot/src/main/java/com/iocextractor/config/boot/MigrationInspector.java)
и [руководство потребителя](../../guides/ru/libraries/config-spring-boot.md#описание-старых-имён-без-переписывания-конфигурации)
задают грамматику шаблонов и проверку каталога. Observer сохраняет исходный
снимок и безопасные ссылки на источники. Сроки совместимости, коды диагностики,
severity и смысл значений принадлежат сервису. Тип метаданных и подсказка замены
не меняют binding Boot.

`MigrationInspectionTest` использует постороннюю collector-модель и настоящий
Boot 4.0.8 Binder. Новое поле списка из более приоритетного источника может
удалить старое поле нижнего списка из связанного результата, хотя оба объявления
остаются видимыми. Поэтому проверка конфликтов выполняется после binding
в валидаторе сервиса. Правила источников и aggregate binding описаны в
[Boot external configuration](https://docs.spring.io/spring-boot/4.0/reference/features/external-config.html).

IOC использует observer для существующего уведомления `smb.encrypt`, после
собственной политики написаний и выбора источников. Он сообщает конкретные
индексы endpoints и сохраняет прежнее поведение пользовательских environment
sources. Преобразование Boolean, запрет двух ключей, rollback compatibility
и подсказки для удалённых ключей остаются локальными.

Пустой снимок объявлений не устанавливает namespace каталога миграций. Выбирайте
каталог по схеме сервиса; отсутствие наблюдений не доказывает правильность
каталога или загруженного кандидата.

## Инварианты

1. Порядок источников сохраняется; raw names сортируются внутри источника.
   Перекрытые и null-valued объявления остаются видимыми. Результат описывает
   объявления, а не окончательное происхождение значений, особенно для списков.
2. Candidate paths и все коллекции результата неизменяемы. При неоднозначном
   разбиении environment-имени сохраняются все кандидаты без выбора одного пути.
3. Фиксированные категории и порядковые номера заменяют произвольные source
   labels в общем результате. Имена и ключи карт всё ещё могут быть чувствительными;
   правила отображения выбирает сервис.
4. Boot aggregate намеренно исключён. Неперечислимые источники, неподдерживаемые
   environment-соглашения и структуры схемы сообщают пробелы покрытия.
5. IOC сохраняет прежние более строгие написания, converters, startup exceptions,
   legacy migration hints и выбор внешних источников для вывода. Его fallback
   совместимости локален; эти ограничения не являются общими правилами библиотеки.

Порядковый номер идентифицирует встречу источника внутри одного результата.
Он не является постоянной идентичностью или стабильным ключом между инспекциями,
рестартами и изменениями графа источников. Исходные labels отсутствуют; raw property
names и dynamic keys всё ещё требуют политики раскрытия сервиса.

## Владение и стоимость исполнения

Вызовы синхронные, изменяемого состояния инспектора между вызовами нет. Дерево
схемы строится заново для каждой инспекции; массив имён каждого перечислимого
источника копируется и сортируется, все подходящие объявления сохраняются
без ограничения выборки. Инспекция миграций проверяет каталог и сопоставляет
его со снимком. Встроенных timeout, input quota или протокола отмены нет.
Количество входов, поведение callbacks и место исполнения выбирает вызывающий
код. Малый bean context сам по себе не ограничивает размер YAML или стоимость
перечисления имён.

Сохраняйте граф подготовленных источников стабильным между инспекцией и binding,
если они должны описывать одного кандидата. Наблюдения не замораживают этот граф
для Binder и не обнаруживают последующее изменение источника. Закрытие check
context приложения не закрывает ресурсы, на которые лишь ссылаются произвольные
property sources; задайте им явного владельца.

## Ошибки и расширение

Неправильный корень схемы — ошибка программирования. Ожидаемые проблемы имён —
факты результата. Ошибки перечисления передаются без переименования в неизвестные
имена. Влияние каждого вида ошибки на сервис или компонент выбирает вызывающий код.

До расширения поддержки квалифицируйте новую структуру схемы или написание
и независимыми name assertions, и настоящим Boot Binder. Добавляйте положительные,
unknown, ambiguous и unsupported cases, сохраняйте идентичность dynamic keys,
используйте источник, чей value getter бросает ошибку, чтобы защитить границу
проверки только имён. Новая версия Boot требует повторной проверки совместимости;
гарантии для всех версий нет.

## Отдельная квалификация

Publication selector `configuration` создаёт разрешённый POM без reactor parent.
Consumer выполняет inspection/migration и точный пример закрытого контекста
вне checkout с упакованными JAR. Приложение владеет Spring Context, SnakeYAML
и своим BOM. Обычное разрешение и Boot BOM различаются Commons Logging
(1.3.5/1.3.6) и JSpecify (1.0.0/1.0.1); оба графа проверяются явно.
Spring dependency downgrades и недоступные managed versions проверяются
отрицательными сценариями. См.
[руководство публикации](../../guides/library-publication.md#configuration-library-admission)
для cold-cache routing, artifact identity и release admission.
