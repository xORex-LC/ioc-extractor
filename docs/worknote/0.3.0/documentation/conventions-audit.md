# DOC-01B.2 — Конвенции, полнота Javadoc и шаблон возможности

Дата: 2026-11-02, Asia/Irkutsk. HEAD:
`5edd3af3a955c7cdd087e8b5917176c58285ae9b`, ветка `docs/quality`.
На входе сохранён незакоммиченный архитектурный пакет `DOC-01B.1`.
Контракт — [R030-DOC](../goals/R030-DOC-documentation.md).

Пакет охватывает `docs/CONVENTIONS.md`, `docs/dev/template.md`, их RU-пары,
навигацию и реестры. По запросу пользователя усилены полнота, конкретность и
единство стиля Javadoc. Код библиотек использован как живой ориентир; массовое
переписывание Java/Javadoc и README других модулей в этот пакет не входит.

## Находки и требования

| ID | Пробел | Результат |
|---|---|---|
| `DOC-C01` | Обязательный публичный Javadoc сам по себе не покрывает сложные внутренние механизмы | Требования распространяются на существенные внутренние типы/алгоритмы/переходы; тривиальные методы не требуют пересказа |
| `DOC-C02` | «Описать контракт» недостаточно для моделей и пограничного поведения | Указаны смысл значений, единицы, null/empty/absent, идентичность/порядок, инварианты, владение/неизменяемость, жизненный цикл, конкурентность, эффекты/отказы и ресурсные ограничения; применяются существенные аспекты |
| `DOC-C03` | Не было общего способа изложения и проверки полезности | Назначение в первом предложении, короткие конкретные абзацы, единый порядок сравнимых контрактов, правила разметки/тегов/наследования и четыре вопроса читателя |
| `DOC-C04` | Общий пример порта не показывал глубину описания поведения | Использован точный фрагмент `DiagnosticBatch.of`; ссылки на executor, MDC и inspection показывают разные контракты и ограничения |
| `DOC-C05` | Распределение root/README/Javadoc могло поощрять либо дублирование, либо потерю структуры | Root сохраняет костяк и основные связи; README владеет локальной структурой/границами/точками входа; Javadoc — точными контрактами. Наличие ссылки не доказывает содержательную полноту README |
| `DOC-C06` | CONVENTIONS и шаблон оставались русскими без обязательных RU-пар после миграции | Canonical EN + отдельные RU; языковая политика сведена с release contract, сохранён старый README anchor |
| `DOC-C07` | Шаблон недостаточно явно направлял к описанию модели, частичных результатов и владельца восстановления | Добавлены применимые характеристики модели, владение/конкурентность, уже выполненные эффекты и безопасность повтора; подробности API делегированы Javadoc, локальная структура — README |

## Живые источники

Полные пути сведены в source set `documentation-conventions` в
[source-sets.tsv](source-sets.tsv). Проверены:

- `DiagnosticBatch`: неизменяемый удержанный образец, точные количества,
  поверхностная неизменяемость и проверки согласованности фабрики.
- `KeyedSerialExecutor`: порядок приёма в рамках ключа/экземпляра, повторные
  отправки, отсутствие гарантий долговременной доставки.
- `MdcScope`: один поток, порядок вложенного закрытия, восстановление затронутых
  ключей, границы поведения при отказах провайдера.
- `PropertyInspection`: упорядоченные наблюдения и покрытие, чувствительность
  имён, отделение результата инспекции от политики принятия конфигурации.
- Root/library POM: применимые настройки doclint отличаются (`all` и
  `all,-missing`); они не заменяют содержательную проверку гарантии.
- `DocumentationConventionTest`: проверяет наличие module README, а не полноту
  содержания. `tools/ci/docs.sh`: проверяет локальные ссылки, а не смысл документа.
- `R030-DOC`, исходные конвенции и соглашение о распределении документации:
  границы EN/RU, README, ADR, generated references и release execution bundle.

В локальном ignored `AGENTS.md` добавлено явное требование читать CONVENTIONS
в начале каждой сессии до правок кода/документации, со ссылками на владение
документацией и Javadoc. Существующая ссылка на Javadoc сохранена;
`CLAUDE.md` использует тот же файл. Нормы остаются в опубликованном CONVENTIONS,
дублирующая политика в skills не создаётся. Локальная правка не войдёт в Git.

Для примера использованы compiler/Javadoc tools JDK 21 через `ToolProvider`:
в текущей среде доступны `jdk.compiler` и `jdk.javadoc`, но отсутствуют отдельные
`javac`/`javadoc` launchers и release-symbol archive. Компиляция использует
`-source 21 -target 21`, classpath собранного diagnostics API и полный исходный
контекст класса. Это проверка буквального примера и doclint, не повторная
квалификация публикации библиотеки и не исполнение всех сценариев её API.
